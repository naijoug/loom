## 目标与成功标准

1. Chat/Settings 只读取 Agent 配置，不加载 Task、不订阅 Planning；高级工作流挂载时才加载任务并订阅一次，离开时解除订阅。Chat 不显示旧任务阶段条。
2. 活动会话补流按已提交日志的字节游标读取，避免每 1.5 秒持有项目锁全量重放两次；保留 seq/身份/损坏数据检查、恢复语义和分页预算。
3. 新增生产路径回归及可复现的长历史读取验证，记录本次代码证据；统一测试指南、契约与计划索引。
4. 对真实模型权限、停止、桌面退出和发布验收分别记录实际结果；缺授权的私人数据外发不以普通修复请求代替授权。

## 非目标

- 不增加多 Agent 编排、依赖或改变 Chat 权限语义。
- 不提交或覆盖用户已有整批未提交工作，不用旧构建/fixture 宣称真实桌面或发布通过。

## 实施步骤

1. 拆分 Agent catalog、Planning 操作与订阅；独立 Chat Shell 和高级工作流路由，复用项目导航与样式。验证 Chat→Task→Chat 的 IPC/监听与 UI 边界。
2. 为活动回合建立可重建日志读索引，以已提交 seq/文件边界提供增量分页；文件截断或身份异常仍失败。新增长历史、分页、写后读取和损坏回归，验证读取不会重新投影完整会话。
3. 完整运行 `pnpm check` 与默认桌面构建；必要的本地预览按 `scripts/debug.sh` 执行，保留证据。核对真实 CLI 探针的安全执行条件；若此前私人 skill 外发边界仍无法收窄，保留待授权项。
4. 更新当前状态与历史文档路由，保存验证日志及源文件校验清单以绑定未提交工作区。

## 风险与回滚

- 日志优化不能信任持久化的派生索引：进程重启仍完整校验权威日志；只优化本进程持有的活动回合，避免缓存掩盖恢复错误。新增缓存可移除回退为完整扫描，磁盘格式不变。
- 路由切换不得丢失高级任务持久化状态，已有项目/任务数据和恢复流程保持兼容。
- 原生窗口/实际模型验收与工程测试分开；真实 CLI 自动读取私人配置的外发边界仍以先前拒绝为约束，不能通过提示词保证隔离。
