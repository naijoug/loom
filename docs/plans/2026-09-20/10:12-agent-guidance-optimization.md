## 目标

统一单 Agent Chat 的当前交付范围、按任务加载的开发约束与验证规则；消除续聊重复历史和发布检查器冻结临时状态的问题。

## 非目标

不变更全局个人技能、不指定默认模型、不引入 API provider、新依赖或通用逐工具审批传输。不在本次优化中完成整个 Chat v2 runtime/storage 重构，不改变真实发布结论。

## 成功标准

- README、AGENTS、需求、测试和 Chat 契约区分当前 Chat、高级 Task、已实现行为和重构目标。
- Ask 明确为当前回合授权；逐工具审批另列能力目标，不把 UI 确认宣称为后端安全边界。
- 开发验证按变更影响选择；保留里程碑与发布完整门禁。
- 原生 resume 只收到新输入；无原生 resume 时历史有预算、有截断标记，最新输入不被静默截断。
- 规划输出默认中文、保留 Todo 解析与 Review 结构化契约。
- 发布状态允许有证据的推进，无证据的 Pass/分发仍被拒绝。
- 新增行为验收案例，区分离线回归与真实模型行为证据。

## 风险与回滚

- CLI 接受 resume 参数不等于真实远端会话存在；运行失败不自动重试有副作用操作，保留错误与转录。
- 历史裁剪可能丢失早期细节，提示词必须明确上下文不完整并保留原始转录；本次不伪造语义摘要。
- 文档变更不代表未完成的 v2 权限/持久化能力已经交付；状态表必须明确。
- 发布检查器只验证证据结构与引用，不能证明签名/公证命令真实运行；分发仍须维护者复核同一候选物。
- 各里程碑可单独回退；无存储 schema 迁移。
