## 已证实发现与方案（本轮补记）

- 故障主页面 commit/finish 和首次绘制已发生；并无可归因的进程终止记录。AppKit 恢复窗口告警、WebContent 部分沙箱告警在正常启动也存在，不能据此关闭安全机制或清除数据。
- 两次原样重启及隐藏/唤醒未复现，原始 OS/绘制触发原因仍未确定。已证实的应用缺口是：`index.html` 原为空 root，入口异步失败没有兜底，Rust 没有区别 page load 与界面就绪的握手，原生没有重新加载入口。
- 修复：静态启动状态 + 小 bootstrap 动态加载 React；主外壳提交后回报当前 document generation。Rust 15 秒无 ready 仅在首次界面尚未就绪时自动重载一次，随后失败使用原生主窗口 sheet；ready 之后不自动刷新。旧 generation 的回执/计时器无效，退出时不恢复。
- 原生菜单提供显式确认的重新加载，不清缓存/历史、不取消或重新发送 Agent 工作。日志只记录阶段、时间、PID、generation 和重试计数，最多 128 条，不记录用户内容/URL/异常原文。
- 原生首次故障注入已通过：page finished 后无 frontend ready → 15 秒仅重试一次 → interface ready。持续故障、最终正常多次重启、完整门禁继续验证。注入只在独立测试构建资源中，不进入正常构建与生产开关。
