# M4-01：旧 Skills 数据只读发现与迁移预览

- 状态：M4-01 只读切片已实现并验收；基线 `46af4ba`（Skills 已完成切片单独提交，M5 勾选同步）。
- 范围：用户只授权只读发现/预览，真实旧数据不接管；四 provider 实测继续 blocked，G1 桌面隔离状态不变。

## 目标与成功标准

提供 Settings → Skills 与无窗口 CLI 的只读入口。默认仅检查已知旧桌面 app data，额外数据目录/旧技能目录须显式指定；安装目标只来自当前用户和已登记项目（CLI 可显式项目）。不扫描整个 HOME，不联网、不执行旧代码，不创建库、锁、备份、staging 或迁移日志，不修改清单/配置/权限。

输出版本化预览、输入文件指纹、来源与旧 ID alias、缓存存在状态、配置存在性、旧 JSON v1/TSV 与 v2 清单状态、copy/symlink 与失效/外部链接提示、同名与别名冲突。所有旧安装始终 legacy-unverified；不根据路径或同名宣布已接管。

## 实施步骤

1. Rust `skills/migration.rs` 实现有界只读扫描，重用旧远程来源规范化及后端目标解析；不复用会初始化目录的 Repository::open 或 Operation。对 metadata symlink、坏/未来 schema、越界路径返回逐项问题，保留其他可读项。
2. 库只读读取复用现有校验；配置仅返回 provider 的 key/model 存在性。缓存只在用户指定根内检查；清单引用的外部路径不成为读授权。指令归属只提示待 M4-03 核验，本轮不宣称已分析/重建使用者。
3. 增加 `skills_plan_migration` IPC 和 `migration-preview` CLI；只暴露 preview，`canApply=false`，不注册 apply/rollback。前端显式点击扫描，展示范围/问题/每项结果，捕获请求归属并隔离晚返回。
4. 合成测试覆盖缺失/损坏/未来版本、重复 alias、无来源安装、合法与失效链接、目录越界、配置脱敏、重复扫描一致、源文件/目录/模式不变及不创建目标库。双端契约、CLI 和前端竞态回归；检查生产包与视觉入口。
5. 更新迁移主计划、索引、契约和 dogfood；独立提交 M4-01。M4-02–05 和真实数据演练保持待办，不能将预览标为迁移完成。

## 风险与限制

预览不是快照事务或执行授权。旧程序并发变化可使结果过时，后续 apply 必须重新校验指纹。目录与文件数/大小有界，报告超限不能假定扫描完整。读取不提供对恶意同用户进程的内核级 TOCTOU 隔离。缓存/旧 bundle 的转接、凭据导入、备份与回滚全部后续实现。

## 验证策略

定向 Rust、IPC/前端测试与 Clippy；里程碑执行 pnpm check 和桌面构建。所有运行以合成临时目录为对象；不读取实际私人旧库作为测试样本，不使用真实 provider 账号。无待确认产品问题。
