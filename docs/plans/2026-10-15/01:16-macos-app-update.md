# Loom macOS 应用内更新

## 目标与范围

按用户确认的方案实现蓝色更新提示、Rust/Tauri 检查/下载/验签/安装/重启，以及 GitHub Releases 发布流水线。React 只展示状态并提交动作；宿主拥有下载地址、安装路径和执行准入校验。

非目标：本轮不发布真实 Release、不生成或读取用户私钥、不改变既有 Beta 分发 Hold、不引入自动强制更新、不扩展 SDK 打包。保持用户已有 REA、工作台和文档改动。

## 当前状态与基线

- 代码基线：`f5a01c1`。开工时主分支已有未提交改动，包含 REA 与工作台 runtime；只在需要的接点增量修改。
- Tauri 2，应用版本 0.1.0，无 updater 插件和 release workflow。
- 旧 Chat/Task 与新 Workbench 双入口共存；进程 supervisor 已有操作租约和退出准入门。
- 开工时 Cargo 声明最低 Rust 1.89；本轮提升为 1.90，锁定实际解析的 updater 2.12.0。最低工具链尚未单独验证。
- 本轮代码实施完成；真实签名、公证和两版升级仍待配置与验收。

## 成功标准

- 两套入口共享更新 UI；无更新时不亮蓝色，支持手动检查、版本说明、下载进度、安装并重启及重试。
- 后台延迟检查且定时检查，无配置或 Web 预览不发真实更新请求。
- 只允许可信 main 窗口操作更新；不能从前端传下载 URL、公钥或安装路径。
- 安装与新任务准入互斥，任何活动 Chat/Task/PTY/Workbench 执行都阻止安装；安装失败释放临时门禁。
- 下载/验签与安装区分，更新结果与脱敏阶段日志持久化；敏感 URL 和认证信息不进日志。
- tag 版本与三处应用版本一致，生成正确架构更新清单、签名更新包和 DMG；先上传产物，保留草稿等待发布验收。
- 发布文档列明所有 Secrets/Variables、首次安装、版本升级、验证及回退策略。

## 风险与处理

- Tauri restart 不能靠退出拦截延迟；安装前必须完成全局空闲判断和数据保存。
- 公钥与签名不匹配必须拒绝；失败日志只记录固定错误分类。
- 发布源必须对客户端可访问；私有仓库采用独立公开发布仓库，不能内置 GitHub token。
- 缺少签名、公证或网络条件时继续实现与离线验证，真实升级明确记为待验收。
- 更新缓存不跨重启，避免持久化包的完整性和陈旧版本风险。

## 实施结果（2026-10-15）

- 已实现：共享更新 Provider、蓝色按钮、手动检查、原生 dialog、版本说明、进度、错误重试和安装前草稿保存。浏览器不可用状态不会调用 native IPC。
- 已实现：Rust updater 服务、可信 main 窗口校验、序列化候选操作、后台检查、内存缓存、官方签名验证、阶段日志和只读运行位置拦截。
- 已实现：全局更新准入租约；WorkBench 两种 runtime 与高层 Planning/Review 纳入执行计数；安装期间拒绝普通退出，已开始退出则拒绝安装。失败释放门禁。
- 已实现：两架构 release workflow、版本/公开配置预检、Apple 签名与公证检查、合并清单、SHA256 和草稿发布；不覆盖公开版本。
- 草稿补充：除安装前强制保存外，编辑后延迟 500ms 保存，避免重启后出现过时的已发送内容；切换界面使用最新快照恢复。设置表单与附件不属于当前草稿格式。
- 为完成编译，对原有 REA 改动中缺失的 PathBuf/PolicyScope 导入、view 引用及 Id 命名空间做最小修正，保留其既有逻辑。仓库还有其他工作产生的 staged/unstaged 改动，未重置或提交它们。
