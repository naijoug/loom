# Chat 导出与回滚

## 导出一个会话

1. 打开项目并选择会话，在「会话」菜单选择「导出会话（JSON + Markdown）」。已归档会话也可以导出。
2. 导出完成后点击「在文件夹中显示」，将**整个导出目录**复制到你的备份位置。默认路径是 `<project>/.loom/chat/exports/<exportId>/`，重复导出会生成新目录，不覆盖旧文件。
3. 用文本/Markdown 查看器打开 `transcript.md`，用 JSON 查看器检查 `session.json` 和 `manifest.json`。导出保留完整正文；分享前自行检查内容，Loom 不会自动上传。

目录包含：

| 文件 | 用途 |
|---|---|
| `session.json` | 完整 v2 会话投影，包括消息、分段、回执、回合配置/状态、续聊句柄和最后事件序号 |
| `transcript.md` | 可独立阅读的转录和执行记录，正文按字面内容保留 |
| `manifest.json` | 导出格式版本、快照序号、是否运行中、日志副本路径/字节边界与缺失说明 |
| `runs/<turnId>/*.log` | 可用的 stdout/stderr 完整行前缀副本；使用相对路径，随整个目录迁移 |

运行中也可导出。它固定已提交的会话序号，并分别捕获日志的完整行前缀；这些边界不一定是同一瞬间，不表示回合最终结果。若准备回滚，先停止回合并等待停止状态，再重新导出。缺失、损坏或未完成的日志尾部会显示在结果提示和 manifest 中；空日志与读取失败不同。

若会话损坏或版本不受支持导致导出失败，先备份原始 `.loom/chat/`，不要清理 journal 或手工降低 schemaVersion。

## 回退到只读取 v1 的旧版 Loom

1. 在当前 Loom 停止所有项目的活动回合，确认不再生成内容。
2. 导出需要保留的新会话，并检查 manifest 的 `inProgress` 为 false、消息/回合数量合理。处理或接受明确列出的缺失证据；不能把有缺失的日志当成完整备份。
3. 退出当前 Loom。备份每个项目的整个 `.loom/chat/`，尤其是 `v2/` 和 `exports/`。不要删除 `v2/`、journal 或迁移前的 `sessions/` 文件。
4. 启动目标旧版本。旧版本只能读取原有 v1 文件；新版迁移没有原地覆盖这些源文件。v2 新会话通过已导出的 Markdown/JSON 阅读，**不要把导出的 JSON 直接放进旧版 `sessions/`，旧版没有 v2 导入能力**。
5. 回到新版时保留/恢复原 v2 备份。新版已有 v2 的会话以 journal 为权威；在旧版对同 ID 会话新增的内容不会自动与 v2 合并。先另存这些内容，再复制到新会话继续。不要手工混拼两个版本的日志。

这条路径提供旧数据保留、独立阅读和备份恢复，不承诺旧应用可以继续原生 v2 会话。完整桌面降级/再升级操作仍属于发布候选验收，离线格式测试不能替代它。
