## 已落地

1. v1 文件只读迁移到 `.loom/chat/v2/sessions/<id>/`；初始记录、元数据/消息 patch、流式增量写入 `events.jsonl`。
2. 每个完整日志记录提交后才发布带 projectKey/sessionId/seq 的统一事件；snapshot 是可重建缓存。
3. 坏尾部只修复未提交字节；完整坏行、错项目、序号缺口、未来 schema 或快照领先日志均失败并保留证据。
4. 实际 ChatPage 使用 `useChatBridge` / `ChatProjection`：监听就绪后才开放发送，快照加载期间缓冲，重复/乱序事件去重补齐，旧响应不覆盖新输出。
5. 活动会话周期补流、窗口回到前台同步；后台会话完成不会抢走当前会话。
6. 草稿按项目/会话隔离；迟到的发送确认只清该次提交的文本，不清另一项目或后来新写的草稿。
7. 损坏会话显示诊断条目，健康会话可继续读取；旧 IPC 正常事件已切换为 `loom://chat-event`，日志写失败使用非持久化 `loom://chat-error`。

## 验收中发现并修复

- 启动时最近项目尚未加载完就误弹“添加项目”：增加 hydration 门槛；最终包启动有已保存项目时不再误弹。
- 项目弹窗显示写死的 Vite/React/Rust、main 和 pnpm dev，并可能借用其他目录的信息：改为匹配目录的真实缓存或“待检测”。最终原生窗口显示空目录的“未识别到预设技术栈 / 本地目录 / 未检测到启动命令”。
- 标题输入的首次自动化操作没有得到完整目标值，未算通过；编辑提交改读当前输入值并增加 IME/单次提交保护，随后明确核对完整输入再保存，原生界面通过。
- Shift+Tab 原先会改变权限：移除该全局快捷键，保留反向焦点导航，已用界面和日志游标共同验证。
- 补修跨项目迟到发送确认清草稿的问题；对同项目另一会话及后来输入均不误清。
