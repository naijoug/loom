# Loom Beta 反馈模板

- **状态**: draft
- **适用阶段**: M0 发布对象与风险边界
- **关联文档**: `docs/release/beta-scope.md`、`docs/release/beta-safety-notes.md`

## 反馈分类

每条反馈必须先归入一种主类：

| 分类 | 含义 | 处理优先级 |
|---|---|---|
| `blocker` | 无法安装、无法启动、无法完成 15 分钟 smoke、数据不可恢复损坏 | 最高 |
| `security` | 权限、脱敏、危险命令、真实 Agent 数据边界或生产误操作风险 | 最高 |
| `bug` | 功能行为错误，但有可绕过路径 | 高 |
| `confusion` | 文案、流程、状态、按钮或概念让试用者误解 | 中 |
| `request` | 新平台、新集成、新自动化或体验增强 | 低 |

如果一条反馈同时属于多类，按更高优先级选择主类，并在“补充标签”中写其它分类。

## 标题格式

```text
[分类] 简短现象 — 阶段/页面/命令
```

示例：

```text
[blocker] 首次启动后无法选择项目 — Project setup
[security] 诊断包疑似包含完整本机路径 — Export diagnostics
[confusion] 不确定真实 Agent 是否会消耗额度 — Agent settings
```

## Triage 规则

- `S0 停止分发`：未脱敏泄露、破坏性命令误执行、安装不可恢复、任务数据损坏。
- `S1 阻塞试用`：目标试用者无法完成安装、首次启动或 15 分钟 smoke。
- `S2 可绕过`：功能失败但可以通过重试、手工命令或跳过步骤继续。
- `S3 建议`：文案、体验、支持范围或后续增强。

## 回收节奏

首轮邀请制 Beta 建议每天收敛一次反馈：

1. 先看 `S0/S1`，决定是否停止继续邀请。
2. 再合并重复 `bug/confusion`，补充安装、权限或 Agent 边界说明。
3. 最后把 `request` 放入后续路线，不与 Beta 安全修复混排。
